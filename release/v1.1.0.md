# Project OS v1.1.0

Turn Claude Code or Codex into a small software team: a PM that plans and asks for your approval, a Developer, an independent QA that runs the tests itself, and a read-only Reviewer. Project state lives in plain files, so a new session continues where the last one stopped.

## What's new

- **Claude Code team out of the box.** `--runtime claude` now installs `project-os-developer`, `project-os-qa` and a read-only `project-os-reviewer` as project subagents, plus `/project-os-start`, `/project-os-task`, `/project-os-qa` and `/project-os-resume`.
- **Self-checking workspaces.** Every workspace ships its validator as `.project-os/check.mjs`, and `planning/formats.md` shows the PM and QA the exact record shapes. They reach zero findings before a task is `done`.
- **Smoother flow.**
  - No separate usage approval before each build.
  - New repositories start without Git until you ask for it.
  - Several approved tasks run back to back.
  - Resume continues already-approved work without asking again.
- **Clearer README** with a three-step Claude start and a sample session.

## Verified

The full workflow ran with the real Claude Code 2.1.110 and Codex CLI 0.147.0 clients. In each, a notes app was planned, built, tested and resumed in a new session, then extended with a feature and a bug fix. See [TEST-REPORT.md](../TEST-REPORT.md). The validator and 46 tests pass on Windows and Linux CI.

## Install

```sh
git clone https://github.com/ferhatcore/claude-codex-project-os.git
cd claude-codex-project-os
node scripts/init.mjs --target ../my-project --name "My Project"
```
